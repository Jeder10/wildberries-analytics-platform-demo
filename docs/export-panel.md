# Панель выгрузок Wildberries

Положите `Wildberries Analytics.exe` в доступную для записи папку рядом с `.env` и запустите двойным щелчком. Файл для Windows x64 включает Python, библиотеки, SQL и шаблон Power BI. На новом компьютере создайте свой `.env` по [примеру](../.env.example) и настройте подключение к локальному PostgreSQL. Панель берёт адрес и имя базы из локальной конфигурации при создании рабочей копии отчёта. Для просмотра отчётов нужен Power BI Desktop. При первом открытии он может запросить учётные данные PostgreSQL.

Для разработки используйте [Выгрузки Wildberries.cmd](../Выгрузки%20Wildberries.cmd) в корне проекта. Этот запуск использует `.venv`. Если положить `.exe` в ту же папку, обе версии увидят тот же `.env`, настройки расписания и журналы. Чтобы перенести уже включённое задание на запуск через `.exe`, откройте новую версию и сохраните расписание нужного источника.

1. Выберите источник в списке слева. Во вкладке **«Ручной запуск»** выберите период. Прошлая неделя идёт с понедельника по воскресенье по Москве. Текущий месяц охватывает завершённые дни с первого числа. В первый день нового месяца используется предыдущий полный месяц. Карточки и остатки загружаются текущим снимком.
2. **«Выгрузить и открыть отчёт»** запускает загрузчик. После успешного завершения Power BI открывает локальную копию на выбранной странице и устанавливает период.
3. **«Открыть сохранённые данные»** сразу открывает ту же страницу с выбранными датами. Данные читаются из PostgreSQL без запроса к Wildberries.
4. Для группового запуска отметьте несколько строк слева или нажмите **«Выбрать все»**, затем **«Обновить выбранные»**. Каждый источник берёт период из своих настроек. Результат можно посмотреть во вкладке **«Журнал»**.

В режиме **«Свои даты»** можно ввести восемь цифр подряд, например `20260101`. После выхода из поля панель покажет `2026-01-01`. Готовую дату в формате `ГГГГ-ММ-ДД` можно вставить из буфера.

В копии Power BI использует DirectQuery. Визуальные элементы запрашивают актуальные строки PostgreSQL при открытии. Ползунок можно передвинуть на другой период с сохранёнными данными. Копии и журналы лежат в игнорируемом каталоге `data/`. Основной PBIP служит шаблоном. [Подключение PostgreSQL в Power BI](https://learn.microsoft.com/power-query/connectors/postgresql)

Когда панель открывает отчёт на выбранном периоде, границы среза сдвигаются к первой и последней фактической дате внутри этого периода. Если записей в нём нет, срез открывается на доступной истории страницы. Воронка предлагает месяцы, по которым есть загруженный итог.

Каждый новый отчёт из панели создаётся в своей папке под `data/report-previews/`. Старую копию можно переместить целой папкой. Данные хранятся в PostgreSQL, и новая копия показывает всю сохранённую историю в пределах выбранного фильтра. Для формирования копии панель использует шаблон `powerbi/Wildberries.pbip` и соседние каталоги `Wildberries.Report` и `Wildberries.SemanticModel`. При запуске через `.exe` эти ресурсы берутся из сборки.

## Сборка Windows

Выполните из корня проекта на Windows с Python x64. Окружение сборки изолировано от рабочего `.venv`.

```powershell
python -m venv build/package-venv
& '.\build\package-venv\Scripts\python.exe' -m pip install -r requirements.txt 'PyInstaller==6.22.3'
& '.\build\package-venv\Scripts\python.exe' -m PyInstaller --noconfirm --distpath dist --workpath build/pyinstaller packaging/windows.spec
```

Готовый файл — `dist/Wildberries Analytics.exe`. Для работы с текущей базой скопируйте его в корень проекта. При обновлении замените исполняемый файл после закрытия панели и завершения её загрузчиков. Настройки и журналы находятся в отдельных файлах рядом с программой. В сборку входят только ресурсы приложения и зависимости.

## Период и ограничения источников

| Источник | Что получает загрузчик | Что показывает выбранный период |
| --- | --- | --- |
| Заказы, продажи и возвраты | Изменения с начальной даты в оперативном окне Wildberries. Сохраняются все полученные операции. | Ползунок по дням оформления заказов или операций продажи и возврата. |
| Карточки и остатки | Доступные карточки или последний снимок по товарам. | Текущий каталог или последний снимок. |
| Финансы | Детализация завершённых недель, которые пересекают выбранный диапазон. | Ползунок по дате финансовой операции. В отчёте участвуют завершённые выгрузки. |
| Воронка | Итоги по месяцам оформления заказа. При выборе части месяца запрос начинается с первого числа. | Срез по месяцам, которые пересекают выбранные даты. |

При паузе API в журнале панели видно следующее время запроса, когда его сообщает загрузчик. При повторе тот же заказ или операция обновляется по ключу. Завершённая история заказов и продаж может продолжить чтение с прежнего курсора после ручного или планового обновления.

## Расписание

Выберите источник и откройте **«Расписание»**. Флажок **«Обновлять автоматически»** включает запуск. Укажите частоту, время по Москве и период данных. При еженедельном запуске можно выбрать день недели, при ежемесячном — число от 1 до 28. Для финансов за прошлый месяц доступны даты с 8-го по 28-е, когда завершились пересекающие месяц недели. Нажмите **«Сохранить расписание»**. Для отключения снимите флажок и сохраните.

Первоначально включены все шесть заданий.

| Источник | Расписание по Москве | Период |
| --- | --- | --- |
| Карточки | Ежедневно в 07:30 | Текущий каталог |
| Заказы | Ежедневно в 08:10 | Изменения со вчерашнего дня |
| Продажи и возвраты | Ежедневно в 11:30 | Изменения со вчерашнего дня |
| Остатки | Ежедневно в 13:30 | Текущий снимок |
| Воронка | Ежедневно в 15:00 | Текущий месяц по завершённым дням |
| Финансы | По вторникам в 17:00 | Прошлая неделя |

Планировщику нужна активная сессия пользователя Windows. При входе он подхватывает прерванное выполнение и проверяет последний пропущенный запуск. Долгая пауза в несколько циклов оставляет выполнению последний плановый период. Для восстановления конкретных пропущенных дат доступен ручной режим. Окно панели можно закрыть. Плановые задания обновляют PostgreSQL в фоне, панель показывает их результат при следующем открытии. [Настройки планировщика Windows](https://learn.microsoft.com/windows/win32/taskschd/task-scheduler-schema)
