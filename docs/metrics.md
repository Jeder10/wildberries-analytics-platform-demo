# Спецификация показателей

Для показателей фиксируем источник, поле, формулу, гранулярность, единицу измерения, дату учёта и исключения. Формулы проверяем на контрольной выборке.

| Показатель | Что нужно определить |
| --- | --- |
| Заказы | Количество заказанных единиц по уникальному `srid` на дату оформления. В общее количество входят отменённые единицы. |
| Отмены заказов | Количество заказанных единиц с признаком отмены по последнему загруженному состоянию. Дата учёта — дата оформления по Москве. Для общего `srid` берём `isCancel` из статистики. Для единиц только из Ленты берём статус `cancel`. |
| Продажи и возвраты | Событие учёта, идентификатор, количество единиц и правило связи возврата с продажей. |
| Выручка | Сумму и валюту, учёт скидок, возвратов и комиссий. Раздельно определить показатели продаж и финансовой реализации. |
| Средний чек | Сумма `retailAmount` по продажам ÷ число уникальных корзин `orderUid`. |
| Остатки | Товар, склад и момент снимка. Для ряда по датам выбрать правило последнего доступного снимка. |
| MoM | Изменение оплаты после возвратов к предыдущему полному месяцу, в процентах. |
| ABC-анализ и эффективность SKU | ABC по оплате после возвратов и доля выкупа по артикулам из воронки. |

## Финансы по отчётам реализации

| Показатель | Поле Wildberries | Расчёт |
| --- | --- | --- |
| Оплата покупателей | `retailAmount` | Сумма оплат по продажам минус абсолютные суммы возвратов |
| Начислено за товар | `forPay` | Сумма начислений за продажи минус абсолютные суммы возвратов |

Единица измерения определяется полем `currency`. Дата учёта берётся из `rrDate`. В [SQL-витрине](../sql/010_daily_product_money.sql) одна группа соответствует отчёту, его типу и периоду, дню операции, артикулу и валюте. В Power BI попадают только завершённые отчёты. Логистика, хранение и штрафы исключены из расчётов. [Поля детализации Wildberries](https://seller.wildberries.ru/instructions/ru/ru/material/how-to-read-fimancial-reports-detalization)

## Анализ продаж и товаров

| Показатель | Как считается | Когда значение пустое |
| --- | --- | --- |
| Средний чек | Для выбранного периода и валюты складываем оплату по строкам продажи и делим на число уникальных `orderUid` среди них. Возвраты исключаются. | Нет продаж или хотя бы одна строка продажи без ID корзины. |
| MoM | `(Оплата текущего месяца − оплата предыдущего месяца) ÷ оплата предыдущего месяца`. Месяц считается целиком по `rrDate`. Используем оплату за вычетом возвратов. | Один из двух смежных месяцев не закрыт полностью или оплата предыдущего месяца равна нулю. |
| ABC | Сортируем товары по оплате после возвратов. В расчёте участвуют только товары с положительной суммой. Группа A включает товар, на котором накопленная доля достигает 80%, B — товар, на котором достигает 95%, остальные попадают в C. При равенстве сумм порядок задаёт подпись с артикулом. | Оплата товара после возвратов равна нулю или отрицательна. |
| Доля выкупа по SKU | Выкупы ÷ заказанные единицы из воронки. Гранулярность — месяц оформления и артикул. Итог считается как отношение сумм за выборку. | Заказанных единиц нет. |

Денежные метрики рассчитываются для одного типа отчёта и одной валюты. Средний чек и ABC реагируют на точные даты среза. Таблица MoM показывает месяцы, попавшие в срез, и берёт итоги за каждый месяц целиком. Полное покрытие означает, что завершённые запросы покрывают весь месяц, уже закончившийся по Москве. Средний чек использует корзину из финансового `orderUid`, а доля выкупа берёт обе части из одной воронки.
